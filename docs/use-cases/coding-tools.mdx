Coding agents often receive more than code. They see logs, stack traces, support tickets, config snippets, test fixtures, environment examples, and production context.

PasteGuard sits between the coding agent and the provider, masks PII and secrets before the request leaves your environment, and restores supported placeholders in responses.

## What Gets Detected

- **Secrets**: API keys, private keys, database passwords, bearer tokens, JWTs, connection strings, and `.env` values
- **PII**: Customer names, emails, phone numbers, locations, account data, test fixtures, comments, and log output

PII detection works [in many languages](/concepts/pii-detection). Full entity lists: [PII Detection](/concepts/pii-detection), [Secrets Detection](/concepts/secrets-detection).

## Codex CLI

Codex users signed in with ChatGPT should use PasteGuard's Codex endpoint:

```toml
model_provider = "pasteguard-codex"

[model_providers.pasteguard-codex]
name = "PasteGuard Codex"
base_url = "http://127.0.0.1:3000/codex"
wire_api = "responses"
requires_openai_auth = true
supports_websockets = false
```

Run a smoke test:

```bash
codex exec --skip-git-repo-check 'Reply with exactly: ok'
```

<Note>
Codex Responses requests are scanned, masked, unmasked, and shown in the dashboard. In route mode, sensitive Codex requests are blocked because PasteGuard does not route Codex Responses traffic to a local provider.
</Note>

## Claude Code

One environment variable:

```bash
ANTHROPIC_BASE_URL=http://localhost:3000/anthropic claude
```

To make it permanent, add to your shell profile:

```bash
export ANTHROPIC_BASE_URL=http://localhost:3000/anthropic
```

<Note>
This requires Claude Code to authenticate with an Anthropic API key. Claude Code signed in with a Claude.ai subscription (OAuth) cannot use a proxy: requests fail with `401`, and subscription credentials are meant for Claude Code's own client flow only. For subscription users, this fork provides a hooks-based integration that masks tool outputs before they enter the context and restores placeholders locally, without touching authentication: see [`integrations/claude-code/`](https://github.com/Mediatros/MyPasteGuard/tree/main/integrations/claude-code).
</Note>

## OpenCode

Set the provider's base URL in `opencode.json` (in the project, or in `~/.config/opencode/opencode.json`). Tested with the DeepSeek provider; other providers use the same key:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "deepseek": {
      "options": {
        "baseURL": "http://localhost:3000/openai/v1"
      }
    }
  }
}
```

For OpenAI, use `provider.openai.options.baseURL` with `http://localhost:3000/openai/v1`; for Anthropic, `provider.anthropic.options.baseURL` with `http://localhost:3000/anthropic/v1`. Then run a smoke test:

```bash
opencode run -m deepseek/deepseek-chat 'Reply with exactly: ok'
```

<Note>
Use API keys with OpenCode behind PasteGuard. OpenCode's Claude Pro/Max login option relies on subscription OAuth credentials, which cannot go through a proxy (see Claude Code above).
</Note>

## DeepSeek Harness

[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (`dsh`) talks to the DeepSeek API over the OpenAI-compatible chat completions protocol. Point PasteGuard's OpenAI provider at DeepSeek in `config.yaml`:

```yaml
providers:
  openai:
    base_url: https://api.deepseek.com/v1
```

Then point `dsh` at PasteGuard with its base URL variable:

```bash
DEEPSEEK_BASE_URL=http://localhost:3000/openai/v1 dsh web
```

Smoke test without the web UI:

```bash
DEEPSEEK_BASE_URL=http://localhost:3000/openai/v1 dsh --profile headless 'Reply with exactly: ok'
```

Requests appear in the dashboard with the `deepseek-harness` user agent, including the session-title request `dsh` sends alongside each conversation.

<Note>
- PasteGuard has a single OpenAI-compatible upstream. While `providers.openai.base_url` points at DeepSeek, every client of `/openai/v1` reaches DeepSeek.
- Keep the `dsh_session_log` extension disabled (its default). When enabled, `dsh` sends the raw session log (user messages, tool results, working directory) as a top-level request field outside `messages`, which PasteGuard does not scan.
- `dsh` Files API uploads (images) are not proxied.
</Note>

## Cursor

1. Open **Settings** -> **Models**
2. Scroll to **API Keys**
3. Enable **Override OpenAI Base URL**
4. Enter: `http://localhost:3000/openai/v1`
5. Add your OpenAI API key

## Other Coding Agents

Most coding agents respect standard provider base URL settings:

```bash
# OpenAI-compatible agents
export OPENAI_API_BASE=http://localhost:3000/openai/v1

# Anthropic-compatible agents
export ANTHROPIC_BASE_URL=http://localhost:3000/anthropic
```

## API Endpoints

| Target | PasteGuard URL |
|----------|----------------|

| Anthropic-compatible agents | `http://localhost:3000/anthropic` |
